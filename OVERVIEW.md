# Обзор проекта: Микросервисная система учета заказов в кафе

## Описание проекта

Данное веб-приложение представляет собой микросервисную систему для учета заказов в небольшом кафе. Система разработана как Single Page Application (SPA) без использования `react-router`, что обеспечивает быструю навигацию между разделами без перезагрузки страницы.

**Основная цель проекта**: Автоматизация процесса приема и обработки заказов в кафе с удобным веб-интерфейсом для официантов и администраторов.

## Основные возможности системы

### Для всех пользователей (включая неавторизованных):

1. **Просмотр меню**
   - Фильтрация по категориям
   - Поиск по названию
   - Отображение цен и доступности

2. **Просмотр заказов**
   - Просмотр списка активных заказов
   - Фильтрация по статусу

3. **Просмотр столиков**
   - Схема зала со статусами столов
   - Информация о вместимости

### Для авторизованных пользователей (Официант):

1. **Управление заказами**
   - Создание новых заказов
   - Изменение статуса заказов
   - Добавление позиций в заказ

2. **Управление столиками**
   - Изменение статуса столов (свободен/занят/забронирован)

### Для администраторов:

Все функции официанта, плюс:

1. **Управление меню** (CRUD операции)
   - Добавление новых позиций
   - Редактирование данных позиций
   - Деактивация позиций

2. **Управление категориями** (CRUD операции)
   - Создание и редактирование категорий
   - Сортировка категорий

3. **Управление столиками** (CRUD операции)
   - Добавление новых столиков
   - Редактирование вместимости
   - Деактивация столиков

## Технологический стек

### Frontend:

- **React 19.2.0** - библиотека для создания пользовательского интерфейса
- **TypeScript 5.9.3** - типизированный JavaScript для надежности кода
- **Vite** - современный инструмент сборки
- **MobX 6.15.0** - библиотека для управления состоянием приложения
- **SCSS/SASS** - препроцессор CSS для стилизации
- **Firebase** - база данных (Firebase Realtime Database)

## Система ролей и прав доступа

### Роли пользователей:

1. **guest** (Гость) - роль по умолчанию
   - Просмотр меню, заказов, столиков
   - Нет возможности редактирования данных

2. **waiter** (Официант) - требует авторизацию
   - Все права гостя
   - Создание и управление заказами
   - Изменение статуса столиков

3. **admin** (Администратор) - требует авторизацию
   - Все права официанта
   - Управление меню (CRUD)
   - Управление категориями (CRUD)
   - Управление столиками (CRUD)

**Пароли для входа** находятся в файле `CREDENTIALS.md`

## Структура данных

### Основные сущности:

1. **MenuItem (Позиция меню)**
   - id, name, description
   - categoryId, price
   - isAvailable, isActive

2. **Category (Категория)**
   - id, name, description
   - sortOrder, isActive

3. **Table (Столик)**
   - id, number, capacity
   - status (free/occupied/reserved/maintenance)
   - location

4. **Order (Заказ)**
   - id, tableId, tableNumber
   - items[], status, totalAmount
   - notes, createdBy

5. **Payment (Платеж)**
   - id, orderId, amount
   - method (cash/card/online)
   - status

## Возможные вопросы на защите

1. **"Почему выбрана микросервисная архитектура?"**
   - Модульность и независимость компонентов
   - Легкость масштабирования
   - Удобство разработки и поддержки

2. **"Как реализован workflow заказа?"**
   - Создание → Готовится → Готов → Подан → Оплачен
   - Каждый статус меняется официантом последовательно

3. **"Как обеспечивается синхронизация данных?"**
   - Firebase Realtime Database обеспечивает синхронизацию в реальном времени
